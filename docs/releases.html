v1.5.0 · 多灯并行管理

● 当前版本

2026-07 发布

一次围绕 多灯并行管理 的大重构。核心从"一个实例控制一盏灯"升级为"一个实例控制任意多盏灯，每盏独立配置、独立控制"。

✨ 新功能 · 多灯连接

  • 无上限的设备数量 — 一个实例可同时管理任意多盏米家 / Yeelight 灯，共享一份托盘图标、一份弹窗、一份快捷键路由
  • 图形化设备列表 — 全新的设置界面，卡片式展示每盏灯的名称 / IP / 型号 / 状态；支持添加、编辑、删除
  • 拖拽排序 — 按住每张卡片左侧的 ⋮⋮ 图标即可拖动，顺序决定弹窗中的显示位置
  • 云端一键多选导入 — 扫码登录小米账号后可勾选多盏设备，一次性批量添加，Token 全部自动填入
  • 配置自动迁移 — 从 v1.4.x 升级时，旧的顶层 device 单对象会被无感转换为 devices: [...] 数组

✨ 新功能 · 弹窗重构

  • 每设备一节 — 弹窗按设备列表顺序为每盏灯渲染独立的一节：设备名、状态、⏻ 开关按钮、亮度 / 色温滑杆
  • 窗口高度自适应 — 一盏灯与旧版差不多，两盏灯约翻倍高，以此类推
  • 关闭所有灯一键按钮 — 底部新增 ⏻ 按钮，一次关掉所有在线设备
  • 设备名智能截断 — 名称过长时自动截断为 xxxx...，按钮位置保持固定
  • 每设备独立防抖器 — 多盏灯拖滑杆时互不干扰

✨ 新功能 · 每设备独立配置

  • 五项电源策略独立开关：软件启停、显示器休眠、系统休眠 / 唤醒
  • 两项显示控制：亮度 / 色温滑杆的可见性
  • 四个全局快捷键：亮度 +/-、色温 +/-，以及独立的调整步进值
  • 快捷键在输入框内按下即捕获；右键输入框直接清空

🐛 修复

  • 设置页"检查更新"按钮走完整的托盘菜单同款流程（含"已是最新版本"弹窗、缓存更新、菜单刷新徽标）
  • 恢复了 v1.4.3 的按键捕获实现（event.state 位掩码解析 + 特殊键 keysym 映射），并接到每设备 hotkey_manager 上
  • 修正 _on_config_saved 保存后重建的灯回调签名（(state) → (state, device_id)）
  • 清理弹窗遗留的 self._light 引用，色温 clamp 时不再报 AttributeError

⚠️ 已知限制

  • 桌面小部件仍为单设备 — 只显示配置里第一盏灯的滑杆，多设备场景请用托盘弹窗或快捷键
  • 托盘右键菜单里的 5 个电源策略开关是"任一为真视为开"的聚合视图
  • 顶层 hotkey 段被废弃，v1.5+ 使用每设备快捷键

v1.4.3 · 电源事件监听

2026-07

✨ 新功能

  • 灯随显示器休眠开关 — Windows 关闭显示器时灯自动关，唤醒时恢复到关闭前的状态
  • 系统休眠时关灯 — 电脑进入睡眠 / 休眠时自动关灯
  • 系统唤醒时开灯 — 电脑从睡眠 / 休眠恢复时自动开灯
  • 三个独立开关，可根据需要自由组合

🐛 修复

  • 修正 GUID_MONITOR_POWER_ON（Win8 已废弃）改用 GUID_CONSOLE_DISPLAY_STATE，Modern Standby 系统也能触发
  • 移除 55 秒空闲判断，避免播放视频时误关灯
  • 使用顶级窗口而非 HWND_MESSAGE，确保能收到系统级广播
  • 调用 RegisterSuspendResumeNotification 显式订阅休眠事件
